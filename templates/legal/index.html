5. Medidas de Seguridad

TechStock implementa multiples capas de seguridad tecnica para proteger la informacion del negocio y de los usuarios:

Autenticacion Segura

Contrasenas cifradas con algoritmo bcrypt (hash irreversible con salt). Las sesiones se gestionan mediante cookies firmadas criptograficamente con itsdangerous (HMAC-SHA1).

Control de Acceso por Roles

Sistema RBAC con cuatro roles (Super Admin, Administrador, Vendedor, Bodeguero) y permisos granulares por modulo. Cada usuario accede solo a lo autorizado.

Registro de Auditoria

Toda accion critica (crear, editar, eliminar) queda registrada con usuario, IP, fecha/hora y descripcion detallada en el log de auditoria.

Proteccion CSRF

Todos los formularios incluyen un token CSRF unico por sesion que previene ataques de falsificacion de solicitudes entre sitios (Cross-Site Request Forgery).

Base de Datos Segura

PostgreSQL con conexiones autenticadas y consultas parametrizadas via SQLAlchemy ORM que previenen inyeccion SQL. Sin consultas SQL crudas.

Validacion de Entradas

Validacion en servidor de todas las entradas. Sanitizacion de nombres de archivo. Proteccion contra path traversal, XSS y subida de archivos maliciosos.

6. Almacenamiento y Proteccion de Datos

Almacenamiento 100% local — Todos los datos se almacenan en la base de datos PostgreSQL del servidor donde esta instalado TechStock. No se envian datos a servidores externos, servicios en la nube ni a terceros. El usuario tiene control total y exclusivo sobre la ubicacion fisica de sus datos. Orionics no tiene acceso remoto a los datos del usuario.
Cifrado de contrasenas — Las contrasenas de los usuarios jamas se almacenan en texto plano. Se utiliza el algoritmo bcrypt con salt aleatorio para generar un hash irreversible, lo que garantiza que incluso en caso de acceso no autorizado a la base de datos, las contrasenas permanecen protegidas.
Eliminacion logica (soft delete) — El sistema emplea un mecanismo de eliminacion logica para registros criticos (productos, clientes, proveedores, categorias). Los registros no se borran fisicamente, sino que se marcan como inactivos, permitiendo la recuperacion ante errores y manteniendo la integridad referencial de los datos historicos.
Archivos subidos — Los archivos que los usuarios suben (fotos de perfil, archivos de backup) son validados en tipo, extension y tamano antes de ser almacenados. Se aplican limites de tamano (fotos: 2 MB, backups: 50 MB) y se sanitizan los nombres de archivo para prevenir ataques de path traversal.
Recomendacion: Para mayor seguridad, se recomienda configurar el acceso al servidor con HTTPS (certificado SSL/TLS) en entornos de produccion, lo que cifra todas las comunicaciones entre el navegador y el sistema.

8. Registro de Auditoria y Trazabilidad

Registro completo — Cada operacion de creacion, modificacion o eliminacion realizada en el sistema queda registrada automaticamente en el log de auditoria, accesible por el administrador y el super administrador.
Datos registrados — Cada entrada del log incluye: usuario que realizo la accion, tipo de operacion (CREATE, UPDATE, DELETE), entidad afectada (producto, venta, cliente, etc.), descripcion detallada del cambio, direccion IP de origen, local asociado y fecha/hora exacta.
Consulta y filtrado — El modulo de auditoria permite filtrar por usuario, tipo de accion, entidad, rango de fechas y busqueda de texto libre, facilitando la investigacion ante incidentes o discrepancias.
Finalidad: El registro de auditoria es un mecanismo de seguridad y cumplimiento normativo. Permite identificar quien realizo cada cambio, cuando y desde donde, garantizando la trazabilidad total de las operaciones conforme a la Ley 527 de 1999 sobre conservacion de registros electronicos.

9. Copias de Seguridad y Recuperacion

Backup completo — El sistema permite generar copias de seguridad completas de la base de datos en formato SQL. Estas copias incluyen toda la estructura y datos del sistema, abarcando 19 tablas.
Almacenamiento local — Los backups se almacenan en el servidor local, bajo el control exclusivo del administrador. Se pueden descargar para almacenarlos en ubicaciones adicionales (disco externo, almacenamiento seguro).
Restauracion — En caso de perdida de datos o falla del sistema, los backups pueden ser restaurados para recuperar la informacion al estado en que se encontraba al momento del respaldo.
Subir backups — Se permite subir archivos de backup (.sql) previamente descargados, facilitando la migracion entre servidores o la recuperacion desde copias externas.
Buena practica: Se recomienda crear copias de seguridad de forma periodica (diaria o semanal) y almacenar al menos una copia en una ubicacion externa al servidor. Restaurar un backup sobrescribe los datos actuales, por lo que siempre se debe crear un backup antes de restaurar.
