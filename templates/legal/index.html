3. Medidas de Seguridad

TechStock implementa multiples capas de seguridad para proteger la informacion del negocio y de los usuarios:

Autenticacion Segura

Contrasenas cifradas con algoritmo bcrypt (hash irreversible). Las sesiones se gestionan mediante cookies firmadas criptograficamente con itsdangerous.

Control de Acceso por Roles

Sistema de roles (Administrador, Vendedor, Bodeguero) con permisos granulares por modulo. Cada usuario solo accede a las funciones que su rol y permisos permiten.

Registro de Auditoria

Todas las acciones criticas (crear, editar, eliminar) quedan registradas con usuario, IP, fecha/hora y descripcion detallada.

Proteccion contra Ataques

Validacion de entradas en servidor, sanitizacion de nombres de archivo, proteccion contra path traversal, inyeccion SQL (uso de ORM parametrizado) y XSS.

Sesiones Protegidas

Las sesiones utilizan cookies con firma criptografica, tiempo de expiracion configurable y soporte para multiples cuentas simultaneas.

Base de Datos Segura

Base de datos PostgreSQL con conexiones autenticadas, consultas parametrizadas via SQLAlchemy ORM que previenen inyecciones SQL.

4. Proteccion y Almacenamiento de Datos

Almacenamiento local — Todos los datos se almacenan en la base de datos del servidor donde esta instalado TechStock. No se envian datos a servidores externos, servicios en la nube ni terceros. Usted tiene control total sobre la ubicacion fisica de sus datos.
Cifrado de contrasenas — Las contrasenas de los usuarios jamas se almacenan en texto plano. Se utiliza el algoritmo bcrypt para generar un hash irreversible, lo que garantiza que incluso en caso de acceso no autorizado a la base de datos, las contrasenas permanecen protegidas.
Eliminacion segura — El sistema emplea un mecanismo de eliminacion logica (soft delete) para registros criticos como productos, clientes y proveedores. Esto permite recuperacion ante errores y mantiene la integridad referencial de los datos historicos.
Archivos subidos — Los archivos que los usuarios suben (fotos de perfil, backups) son validados en tipo, extension y tamano antes de ser almacenados. Se aplican limites de tamano (fotos: 2 MB, backups: 50 MB) y se sanitizan los nombres de archivo para prevenir ataques.
Recomendacion: Para mayor seguridad, se recomienda configurar el acceso al servidor con HTTPS (certificado SSL/TLS) en entornos de produccion, lo que cifra todas las comunicaciones entre el navegador y el sistema.

5. Control de Acceso y Permisos

El sistema implementa un control de acceso basado en roles (RBAC) con permisos granulares:

Rol Descripcion Acceso por Defecto
Administrador Control total del sistema Todos los modulos, configuracion, usuarios, backups, auditoria, importacion
Vendedor Operacion comercial diaria Productos (lectura), ventas, POS, clientes, caja, historial de ventas
Bodeguero Gestion de almacen e inventario Productos, categorias, inventario (entradas/salidas), proveedores
Permisos personalizados — El administrador puede asignar permisos individuales a cada usuario, independientemente de su rol. Esto permite configuraciones especificas como dar acceso a reportes a un vendedor o restringir modulos a un administrador junior.
Sesion obligatoria — Todas las paginas del sistema requieren autenticacion. Un usuario que no haya iniciado sesion sera redirigido automaticamente a la pantalla de inicio de sesion. Las sesiones tienen un tiempo de expiracion configurable.
Importante: El administrador es responsable de asignar roles y permisos adecuados a cada usuario. Se recomienda aplicar el principio de minimo privilegio: cada usuario debe tener solo los permisos necesarios para realizar sus funciones.

6. Registro de Auditoria y Trazabilidad

Registro completo — Cada operacion de creacion, modificacion o eliminacion realizada en el sistema queda registrada automaticamente en el log de auditoria, accesible unicamente por el administrador.
Datos registrados — Cada entrada del log incluye: usuario que realizo la accion, tipo de operacion (CREATE, UPDATE, DELETE), entidad afectada (producto, venta, cliente, etc.), descripcion detallada, direccion IP de origen y fecha/hora exacta.
Consulta y filtrado — El modulo de auditoria permite filtrar por usuario, tipo de accion, entidad, rango de fechas y busqueda de texto libre, facilitando la investigacion ante incidentes o discrepancias.
Finalidad: El registro de auditoria es un mecanismo de seguridad y cumplimiento normativo. Permite identificar quien realizo cada cambio, cuando y desde donde, garantizando la trazabilidad total de las operaciones.

7. Copias de Seguridad y Recuperacion

Backup completo — El sistema permite generar copias de seguridad completas de la base de datos en formato SQL. Estas copias incluyen toda la estructura y datos del sistema.
Almacenamiento local — Los backups se almacenan en el servidor local, bajo el control exclusivo del administrador. Se pueden descargar para almacenarlos en ubicaciones adicionales (disco externo, almacenamiento seguro).
Restauracion — En caso de perdida de datos o falla del sistema, los backups pueden ser restaurados para recuperar la informacion al estado en que se encontraba al momento del respaldo.
Subir backups — Se permite subir archivos de backup (.sql) previamente descargados, facilitando la migracion entre servidores o la recuperacion desde copias externas.
Buena practica: Se recomienda crear copias de seguridad de forma periodica (diaria o semanal) y almacenar al menos una copia en una ubicacion externa al servidor. Restaurar un backup sobrescribe los datos actuales, por lo que siempre se debe crear un backup antes de restaurar.

Comercio electronico y mensajes de datos:

Ley 1273 de 2009

Delitos informaticos:

  • Proteccion contra acceso abusivo a sistemas

Estandares internacionales — El sistema sigue principios alineados con el RGPD (Reglamento General de Proteccion de Datos europeo) y la norma ISO 27001 en cuanto a: minimizacion de datos, limitacion de proposito, integridad y confidencialidad, y rendicion de cuentas.
